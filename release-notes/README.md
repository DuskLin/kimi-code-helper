# 中文发布说明

CI 自动生成三个栏目：**新增功能 / 问题修复 / 其他改进**。范围为当前 tag 与沿主分支历史可达的上一个正式版本 tag 之间的非合并提交；首次发布包含截至当前 tag 的全部提交。预发布版本可对比前一个预发布 tag，正式版本不会以预发布 tag 为基线。

- `feat:` / `feat(模块):` 归入新增功能。
- `fix:` / `fix(模块):` 归入问题修复。
- 其他提交归入其他改进。
- 中文提交标题直接展示，并附提交链接。
- 英文标题默认根据修改的文件生成中文模块摘要，例如“完善项目文档”，不会自动逐句翻译或推断代码行为。需要精确描述时，在提交正文添加一行 `Release-Note-zh: 中文修改说明`。

例如：

```text
fix(updater): handle interrupted downloads

Release-Note-zh: 修复更新下载中断后无法重试的问题
```

也可在此目录添加版本文件，例如 `0.2.0.md`，提供人工整理的版本级摘要。文件必须包含 `## 新增功能`、`## 问题修复`、`## 其他改进` 三个标题，其内容优先于提交摘要。建议把它与该版本代码一起提交，再创建 tag。手动重建旧 tag 时，采用所选工作流版本中的发布工具与版本说明文件，但应用本身仍从原 tag 构建。

Release 正文中的 `<!-- kimi-release-notes:start -->` 和 `<!-- kimi-release-notes:end -->` 标记之间是自动生成区域，重跑时会更新；手写安装说明等内容请放在标记之外，会原样保留。已有 Release 没有这些标记时，自动摘要加在原正文前面，原正文不会被删除。更新说明不会自动把草稿变为正式发布。
